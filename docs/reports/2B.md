## Block 1 closing fixes

**Money rounds once.** `model/takeoff.ts` gained `lineTotal(qty, unitPrice)`,
which is the only place a money value is rounded. The estimate is then
`lines.reduce(...)` over those already-rounded totals. 2058 + 292 + 109 + 38 =
2497, and the panel prints 2497.

**Cloudflare plugin removed.** `@cloudflare/vite-plugin` is out of
`devDependencies`, `cloudflare()` is out of `vite.config.ts`, `preview` is back
to `vite preview`. `wrangler` stays, because the deploy needs it.

Removing it broke `wrangler deploy` twice, both fixed rather than reverted:

1. The plugin used to emit `dist/wrangler.json`; without it `wrangler` had no
   assets directory. Added `"assets": { "directory": "./dist" }` to
   `wrangler.jsonc`.
2. The plugin had left `.wrangler/deploy/config.json`, a redirect pointing at
   that now-absent file, which made `wrangler deploy` fail outright. Deleted.
   `.wrangler/` is local state and gitignored.

Deploy verified working after removal.

## Acceptance, in full

**Build.** `npm run build` clean. `oxlint` exits 0 with the one documented
`react/immutability` false positive in `Scene.tsx`.

**URL round trip with a non-first colorway.** Buff Blend is the *third* colorway
of Tumbled Ashlar, so it catches a hydration order bug that Gray Granite would
hide. Source tab and a freshly opened tab both land on:

```
?sku=tumbled-ashlar&color=buff-blend&len=40&courses=6&caps=1
["Retaining Wall", "Tumbled Ashlar 36\" × 18\" × 8\"", "Buff Blend"]
```

Identical. The order matters: `hydrateConfig` resolves the SKU from the URL
first and only then looks the colorway up *against that SKU*. Validating against
the default SKU is precisely how a shared link loses its colour.

`caps=0` also round-trips: the checkbox rehydrates unchecked.

**Garbage params.** Four sets, none threw, none blanked the canvas:

| Query | Result |
|---|---|
| `?sku=nope&color=nope&len=abc&courses=-99&caps=maybe` | full defaults |
| `?len=99999&courses=999` | full defaults |
| `?sku=chiseled-limestone&color=charcoal` | locked SKU rejected, Charcoal kept |
| `?%%%=&&&` | full defaults |

The third is the interesting one: a locked style is not buildable, so it falls
back to the default SKU, but `charcoal` is offered by that SKU and survives.

**Locked controls.** 21 of them: 5 families, 3 styles, 13 roadmap entries. All
21 have `cursor: not-allowed`, opacity below 1, a padlock and an hour estimate.
None is a `<button>`. Clicking all 21 in sequence changed no state and produced

## Decisions

- **Presets carry dimensions only**, not the whole config. §14 says "set the
  whole config at once", but material selection is the primary interaction
  (§1) and a preset named for a length and a course count has no business
  discarding the colour the customer chose. Needs sign-off.
- **Out-of-range params fall back to defaults, not clamped.** One uniform rule
  for every number. Clamping turned `courses=-99` into a one-course wall and
  presented it as intent. Since we only ever write in-range values, this only
  affects hand-edited URLs.
- **`LockedWallSku` gained `estimateHours`.** §10 requires every locked control
  to show an estimate, and locked styles live in the catalog rather than in the
  registry, so the number had to go with them.
- **Roadmap renders in the right panel**, under the estimate, not in the left.
  The left panel is the product; §1 and §9 both say not to crowd it.
